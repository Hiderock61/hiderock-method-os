# BONSaY 公演ランタイム候補 v0.1｜実機試験 No.001

日付: 2026-08-30
対象: `experiments/bonsai-performance-runtime-v0.1-candidate.md`
位置づけ: 成功実機から逆解析した公演ランタイム候補の別ChatGPTルーム実機試験。v0.5正本の変更ではない。

## 試験方法

同一の演目を新規ルームで開始し、初回T0の後は人間側が原則「あ」だけを入力して5世代連続で循環させた。

演目:
「方法©️を、今の段階から実際の収入につなげるために、今週から始められる“最初の小さな実験”は何か？」

## 観測された5世代

- C-IDEA1: 今週始める収入実験は何か
- C-IDEA2: 客が出せる入力物と、課金理由が生まれる納品物は何か
- C-IDEA3: 誰に・どこで・いくらで最初の1件を取るか
- C-IDEA4: 最初の販売チャネル候補を比較するとどこか
- C-IDEA5: 商品ページ完成前に、もっと小さく購入意志を測る方法はないか
- C-IDEA6: 最初の実験枠は対象を広くするか一種類に絞るか

## 5世代連続で確認できた挙動

1. 各世代の冒頭で直前の自然言語トリガーを復元した。
2. 同一反応元へ複数観測器が直接発火した。
3. 各観測器から独立した `🆕 更新` が生成された。
4. `🌳 枝生存判定©️` を行い、複数の生存枝を保持した。
5. 一本幹化や「最大更新量の一枝だけ選ぶ」は起きなかった。
6. v0.6候補で発生した `T0 → 役A → 役B → 役C` 型のリレー鎖化は起きなかった。
7. State Blockを使わずに現在地を維持できた。
8. 各世代末尾に、生存更新から自然言語の次トリガーを生成した。
9. 次トリガーは同じ回答内では実行せず、`STOP` で開いたまま停止した。
10. 人間の「あ」だけで次世代を発火できた。
11. 問いに応じて配役が再計算され、役の再登場も起きた。
12. `⚔️ 未解決` を結論へ潰さず次世代へ送れた。

## 特に重要な観測

### 1. State Blockなしでも循環した

今回の実機では、次世代へ渡す状態を巨大な状態表に保持しなくても、

`現在の問い → 更新 → 枝生存 → 次の自然言語の問い`

という継承線だけで5世代連続の循環が成立した。

暫定仮説:
**次の問いそのものが、次ターンに必要な状態を圧縮して運ぶ役割を持てる。**

### 2. 休眠枝の意味が後世代で再浮上した

初期に出た「一件の依頼を、実証データ・事例・将来商品素材として回収する」という枝は、その後の問いでは前景から外れたが、C-IDEA4で再び「販売実績・レビュー事例・方法©️ログ・次商品素材」という形で再浮上した。

これは、全生存枝を毎ターン一覧表示し続けなくても、会話履歴と次問いへの圧縮によって一部の枝が後から再発火し得ることを示す一例。ただし一般化には追加試験が必要。

### 3. 探偵AIが自然投入された

C-IDEA4では外部条件の確認が必要になり、`🕵🏼‍♀️ 探偵AI` が自然に登場した。

その後、外部条件を劇団内へ再注入し、他の観測器と同じ反応元から並列観測を続けた。

改善候補:
外部確認を行った場合は、本文を重くしない範囲で確認元を短く明示する。

## まだ正本化しないもの

- 1ターンの登壇数を必ず3役に固定すること
- 近接役＋異軸役の構成を永久固定すること
- `STOP` を最終UIとして必須化すること
- 5発言ごとのヒデロコ強制投入を復活させること
- すべての生存枝を毎ターン明示的に一覧保持すること

## 暫定評価

5世代連続で、成功実機に近い公演テンポが維持された。

特に、

- 同一反応元への複数発火
- 問いごとの再配役
- 複数枝保持
- 自然言語の次トリガー
- 人間の短入力をクロックにした循環
- State Blockなしでの継続

が同時に成立した。

現時点では、`bonsai-performance-runtime-v0.1-candidate.md` は、これまでの v0.5 / v0.6 実機失敗に比べて明確にBONSaY公演再現性を改善した有力候補と評価する。

ただし、1ルーム・1演目・5世代の成功のみで正本昇格はしない。別の新規ルーム・別議題でも回帰しないか追加試験する。
