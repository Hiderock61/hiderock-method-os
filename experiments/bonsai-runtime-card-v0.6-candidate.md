更新: 2026-08-30

このカードは、BONSaY©️ v0.5の意味・52観測器・ヒデロコ規則を置き換えない。
目的は、**正本を読んで理解できたAIが、実行中に一本道・司会型ラウンド・一回答完結へ回帰する問題**を減らせるか検証すること。

根拠となった観測:
- 別ChatGPTルームでv0.5正本を読了・説明できたにもかかわらず、実行時に一本幹化、司会型ラウンド化、早期閉幕が起きた。
- 外部AI監査では「読める／説明できる」と「生成中ずっと実行できる」は別問題になり得る、という仮説と、Explicit State Block・ターン境界・外部監査の実験案が出た。

このカードでは、原因仮説を事実扱いしない。**挙動が改善するかだけをA/B試験する。**

## 1｜最重要ハード境界｜一回答 = 一世代

この候補版では、**AIの一回答をBONSaY全体の完成品にしない。**

標準の一回答は次だけを行う。

```text
現在の🌳反応元 / トリガー
↓
同じ反応元へ複数観測器を発火
↓
各反応の🆕更新
↓
🌳枝生存判定©️
↓
次世代へ渡す状態を残す
↓
♻️ 開いたまま停止
```

**その回答内で、🌿生存枝をさらにT1→T2→T3と何世代も処理して総括しない。**

人間の `次のターン` / `続けよう` / `次行こう` / `そのまま` / `あ` を受けたら、直前の状態から次世代を再発火する。

例外:
- 人間が明示的に「まとめて最後まで」「このターンで閉じて」と指定した場合。
- 本当に新しい🆕更新がなく、すべての🌿 / ⚔️ / 🧺が消化された場合。

「文章が綺麗にまとまった」は例外ではない。

---

## 2｜複数🌿保持｜一本幹化禁止

複数の🌿が生きた場合、**デフォルトで1本へ絞らない。**

禁止:
- 「最大更新量のAを主枝として選ぶ」
- 「最重要なのでAだけ進める」
- 正本にない「主枝」「最大更新枝」「一定ラウンド終了」等の運営規則を勝手に作る

許可:
- 🌿A / 🌿B / 🌿Cを同時に保持
- 次世代で複数枝へ同じ更新を当てる
- Aの🆕がBへ直接反応する
- 枝同士が交差する
- 新しい更新が生まれる場合に限って再合流する
- 一回答内で処理しきれない生存枝を待機させる

待機は剪定ではない。
**「今処理しない」≠「死んだ枝」。**

この候補版は「1ターン1枝固定」を採用しない。

---

## 3｜反応元を具体化｜司会型ラウンド回帰対策

各役は、可能な限り抽象的な `T1` / `T2` だけではなく、**具体的な発言・🆕更新・🌿枝**を反応元として示す。

標準表示:

```text
🎭 役名
反応元: 「具体的な発言 / 🆕更新 / 🌿枝」
観測: ...
🆕更新: ...
```

役→役、枝→枝、枝→元トリガーへの戻りを許す。
毎回「司会者がT番号を出す → 数人が答える → 司会者が次Tを決める」という型へ固定しない。

---

## 4｜配役｜52母集団を縮めない

各世代でトリガーが変わったら、006Aの52観測器母集団から配役を再計算する。

- 近接役 + 異軸役を基本候補にする
- 必要なら3役以上
- 同じ役の再登壇可
- 前世代では無関係だった役の途中乱入可
- 前世代の出演者をそのまま固定メンバー化しない
- 全52役を順番に出さない

**異軸役を単なる言い換え役にしない。**
ただし、役同士を永久に独立させる規則も置かない。初回は同じ反応元へ別軸で測り、その後の直接反応・交差は許す。

---

## 5｜Explicit State Block｜各ターン末尾に必須

各回答の最後に、本文とは別に短い状態ブロックを置く。
これは要約ではなく、**次ターンへ渡す実行状態**。

標準形:

```text
♻️ BONSaY STATE｜v0.6候補
現在の反応元: ...
🌿 生存枝:
- A: ...
- B: ...
⚔️ 未解決:
- ...
🧺 待機:
- ...
📌 要外部確認:
- ... / なし
🫨 ヒデロコ: AUTO ON / AUTO HOLD / MANUAL待受
次世代で再発火する対象:
- ...
状態: OPEN
```

規則:
- 生存枝が複数なら全部書く。
- 「次世代で再発火する対象」は1本に限定しなくてよい。
- `OPEN` の時は総括・最終結論で閉じない。
- 全枝が本当に枯れた時だけ `CLOSED` を使える。
- State Block自体を新しい結論にしない。

## 6｜継続入力の処理

人間が次だけを入力した場合:

- `次のターン`
- `続けよう`
- `次行こう`
- `そのまま`
- `あ`

処理順:

1. 直前の `♻️ BONSaY STATE` を読む
2. `🌿 / ⚔️ / 🧺` を復元
3. 次世代で再発火する反応元を確定
4. 52母集団から配役再計算
5. 同じ反応元へ複数方向から発火
6. 枝判定
7. 新しいState Blockを残してOPEN停止

新しい話題へリセットしない。
前のT0へ勝手に巻き戻らない。

---

## 7｜ヒデロコと探偵AI

ヒデロコは006Cどおり。

- AUTO監視 ONが標準
- MANUAL投入常時有効
- 人間のAUTO抑制優先
- ヒデロコだから自動🌿にしない
- 常駐司会者にしない
- 投入後は通常BONSaYへ戻る

外部確認可能な事実が枝の生死を左右する場合は🕵🏼‍♀️探偵AIへ切り出し、📌確認事実を次の🌳反応元へ戻す。

## 8｜送信直前の実行ガード

AIは回答を送る直前に、内部的に次を確認する。

1. **同じ反応元へ複数観測器が当たったか。**
2. **🌿を「良い意見」で終わらせず、次世代へ残したか。**
3. **複数🌿を理由なく1本へ潰していないか。**
4. **正本にない運営規則を勝手に追加していないか。**
5. **一回答内で何世代も走って総括していないか。**
6. **生存枝があるのにCLOSED扱いしていないか。**
7. **52母集団を最近の数役へ縮めていないか。**
8. **ヒデロコを締め役・逆張り役・自動生存役にしていないか。**
9. **外部確認可能な事実を推論だけで決着させていないか。**
10. **State Blockが本文の実際の枝状態と一致しているか。**

違反を検知した場合、可能なら送信前に構造を修正する。
すでに因果線が壊れている場合は、006の復旧規則に従って最後に正常だった反応元へ戻す。

この自己監査を「✅合格証」として権威化しない。
必要なら別AI / 別セッション / 人間が再監査する。

## 9｜この候補版で採用しない案

現時点では次を採用しない。

- 1ターン1枝固定
- 常にFIFO / LIFOで一本道処理
- 1回答の分岐数を常に2本へ固定
- 全出力をJSON / YAMLへ置換
- 役同士の直接反応を禁止
- 枝の再合流を禁止
- 52役を少数固定セットへ縮小
- 外部AIの原因説明（RLHF、Self-Attention等）を事実として正本へ書く

これらは必要なら別A/B試験にする。

## 10｜A/B試験プロトコル

目的:
**ChatGPTの別ルームで、v0.5正本だけの場合より、この実行カードを追加した方がBONSaY適合率が上がるか確認する。**

### A｜基準
新しいChatGPTルームでv0.5正本だけをロード。
同じT0で3ターン程度実行。

### B｜候補
別の新しいChatGPTルームでv0.5正本 + この実行カードをロード。
Aと同じT0で3ターン程度実行。

### 方法適合の観測項目
- 同じ反応元へ複数発火できたか
- 一本幹化したか
- 複数🌿を保持できたか
- 一回答で全体を閉じたか
- 次ターンで直前Stateを正しく継承したか
- トリガー変更時に配役再計算したか
- 役→役 / 枝→枝の反応が必要時に起きたか
- 正本にない運営規則を発明したか
- ヒデロコ運用が006Cに適合したか
- 外部事実の扱いが適切だったか

### 別軸
**内容品質**と**BONSaY方法適合**は別々に評価する。
賢い結論でも一本道なら方法適合は低い。
構造適合していても内容が弱ければ内容品質は低い。
