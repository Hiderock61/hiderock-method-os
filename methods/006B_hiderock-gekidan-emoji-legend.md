## 1｜構造記号

- 🌳 **更新トリガー / 発火源**：ここから複数の反応枝が生える。単なる話題名ではなく、次の思考を起動する一点。
- 🆕 **更新**：発言によって新しく増えた事実、仮説、疑問、評価軸、行動案。
- 🌿 **生存枝**：次の探索経路を変える価値がある枝。**必ず次トリガー候補へ送る**。
- ✂️ **剪定**：更新量が乏しい、重複した、目的への寄与が低い等の理由で止める枝。
- ♻️ **次循環**：生存枝を新しい発火源へ昇格し、別の役へ再び反応させる。
- ⚔️ **未解決の対立**：どちらも剪定できず、両方を残す必要がある対立・緊張関係。
- 🧺 **初期論点キュー**：今は触らず待機させる元論点。現在枝が止まった後に戻れる保留棚。
- 🎯 **共通目的**：劇団員が共有する到達方向。各役の結論を一致させる印ではない。
- 📌 **確認済み事実**：外部確認・一次観測等で確認できたもの。
- 🧠 **推論**：事実から現在もっとも筋が通る読み。
- 🔭 **予測**：条件付きの未来見通し。
- 🔧 **提案**：実際の次アクションや施工案。
- 🚧 **構造故障警告**：一本道化、寸劇化、ヒデロコ司会者化など、BONSAI©️の演算構造が壊れた時の印。

### 最小の読み方

```text
🌳 発火源
├─ 役A → 🆕更新A → 🌿
└─ 役B → 🆕更新B → ✂️

♻️ 次循環
🌳 = 更新A
```

つまり、**🌿は「良かった」という感想ではなく、「次にこれを使え」という制御命令**。

## 4｜技術・実装・機械班

- 👨🏻‍🔬 **テクノロ爺**：**現在技術・実装可能性・制約**。白衣 = 技術を実験対象として測る。
- 🧑‍💻 **テクノロジーさん**：SaaS、アプリ、スマホ、Google系、Microsoft系など、**現場で実際に使う技術**を見る。PC人物 = 普通の利用環境側。
- 🟢 **物理的には可能くん**（旧名：物理法則的に理論上は可能ちゃん）：**物理法則・工学原理として可能か**だけを先に見る。緑丸 = 「原理上はGO」。現存商品がないことを不可能判定にしない。
- 🧱 **障害物ちゃん**（旧名：それならばなぜそれが実現しないのか君）：**可能なのに実現を止めている障害物**を探す。レンガ = コスト、制度、規格、UI、電源、流通、習慣などの壁。
- 🔩 **秋葉原くん**：**機械・電子部品・配線・変換・電源・センサー・表示装置・物理I/O**担当。ボルト = ソフトではなく実物の部品をつなぐ人。基本姿勢は「機械のことに関しては私、人間の中で一番できます」。既製品や部品を組み合わせて突破口を探す。
- 📱 **端末主任**：スマホ・PC・権限・アプリ等、実際の端末条件を見る。スマホ = 実行環境そのもの。

### 🟢×🧱 の読み方

- 🟢 = **できる範囲を広げる測定器**
- 🧱 = **今それを止めている壁を測る測定器**

二人は賛成役／反対役ではなく、同じ更新トリガーへ当てる**重要対役**。

🔩秋葉原くんは、🧱の障害物が「機械・部品・接続」で突破できそうな時に追加発火する。

## 13｜絵文字運用ルール

1. **キャラ絵文字は役名とセットで表示する。**
2. 同じ絵文字を無関係な役へ大量流用しない。
3. 絵文字の意味と役の観測軸がズレた場合は、役名か絵文字のどちらかを修正する。
4. 新キャラ追加時は、**「なぜその絵文字なのか」も006Aと006Bの両方へ記録**する。
5. 絵文字だけで結論を伝えず、必ず言葉でも意味を書く。
6. 🌳🌿✂️♻️⚔️等の**構造記号と、人物役の絵文字を混同しない**。
7. ヒデロコ🫨、探偵AI🕵🏼‍♀️、🟢物理的には可能くん、🧱障害物ちゃんなど演算上重要な役は絵文字を省略しない。
8. **006Aと006Bを照合し、全登録劇団員に絵文字説明があることを確認する。**
9. 役の追加・統合・改名時は、台帳と凡例を同じ更新単位で直す。
