# 006｜ヒデロツク劇団方法©️（BONSAI©️） v0.3｜分岐循環版

## Global short name

**BONSAI©️**

## ⚠️ 最重要｜これは「複数キャラ会議」ではない

ヒデロツク劇団方法©️（BONSAI©️）は、複数の役者が順番に感想を言うパネルディスカッションではない。

**重要な更新トリガー1個に対して、同じ反応元から必ず2方向へ枝を出し、生きた枝そのものを次の更新トリガーにして再分岐する。**

1. **近接役1名**：その更新を最も直接深掘りする専門役。
2. **異軸役1名**：別カテゴリ・別評価軸から同じ更新を見る専門役。

2名は、同じ更新トリガーへ反応しなければならない。

```text
❌ 一本道
Aが発言 → Bが発言 → Cが発言 → Dが発言

❌ 見た目だけBONSAI
元文章の論点1 → 近接＋異軸 → 生存 → 終了
元文章の論点2 → 近接＋異軸 → 生存 → 終了
元文章の論点3 → 近接＋異軸 → 生存 → 終了
最後に総まとめ

✅ BONSAI©️
🌳 更新トリガーT0
├─ ① 近接役A → 🆕更新A
└─ ② 異軸役B → 🆕更新B
        ↓
    🌳 枝生存判定©️
        ↓
    🌿 更新Aが生存
        ↓
🌳 T1 = 更新A
├─ ① 近接役C → 🆕更新C
└─ ② 異軸役D → 🆕更新D
        ↓
    再び枝生存判定©️
```

**BONSAI©️の単位は「役者の発言」ではなく「更新された枝」。**

**枝が🌿生存したのに、その枝を次へ送らず別の元論点へ横移動した場合、循環は成立していない。**

## 目的

共通する未来へ向けて必要な専門観測役だけを起動し、重要な更新トリガーごとに **近接役1名＋異軸役1名** の2方向へ分岐させる。

各枝を **枝生存判定©️** にかけ、価値のある枝だけを残す。生き残った枝を次の更新トリガーへ昇格させ、必要なら外部事実を注入しながら、仮説・問い・行動案を更新していく。

**思想は一つ、観測装置は複数。枝は増やすが、全部は育てない。**

「ヒデロツク側」とは、ヒデロツクの現在の仮説を守ることではなく、ヒデロツクが望む未来の側に立つこと。

- 目的 = 共通
- 観測点 = 別々
- 結論 = 一致する必要なし
- 分岐 = 意図的に作る
- 剪定 = 更新価値で決める

劇団方式の単位は「意見」ではなく「更新」。

> **共通目的 × 異なる観測点 × 二方向反応 × 枝生存判定 × 再分岐 × 必要時の外部調査 = BONSAI©️分岐循環**

## 🌳 二方向反応ルール©️

### 1｜更新トリガーを1個選ぶ

更新トリガー候補：

- 新しい事実
- 新しい仮説
- 反証
- 問題発見
- 重要な提案
- 制約の発見
- 本人の新しい観測

確認・相づち・単なる言い換えは更新トリガーにしない。

複数の論点がある入力でも、最初から全部をT1、T2、T3と並列処理しない。**現在もっとも更新量が大きい1個を選ぶ。**

### 2｜同じトリガーへ2名を当てる

**① 近接役**：その更新を最も直接深掘りする。

**② 異軸役**：別カテゴリ・別評価軸から同じ更新を見る。

異軸役は「反対役」ではない。必要なのは **違う測定器を2個当てること**。

### 3｜反応元と更新を可視化する

```text
## 🌳 T3｜更新トリガー
「○○」

### ① 👩‍💻物理法則的に理論上は可能ちゃん｜近接反応
反応元：T3
内容：...
🆕 更新A｜...

### ② 🧑🏻‍💻それならばなぜそれが実現しないのか君｜異軸反応
反応元：T3
内容：...
🆕 更新B｜...

### 🌳 枝生存判定©️
- 🌿 A：生存｜理由...
- ✂️ B：剪定｜理由...
```

### 4｜🌿生存は「次に使う」という意味

枝生存判定©️は飾りラベルではない。

**🌿生存と判定した枝は、原則としてその枝自身を次の更新トリガーへ昇格させる。**

```text
T0
├─ A 🌿
└─ B ✂️

次は
T1 = A
├─ C
└─ D
```

生存枝があるのに元入力の別論点へ横移動してはいけない。

例外は次の3つだけ。

1. 生存枝が停止条件に達した。
2. ユーザーが別の枝・別議題へ移動を指示した。
3. より高優先の新事実が割り込んだ。

### 5｜深さを作ってから横へ行く

BONSAI©️は「元文章を項目別に2人ずつ査定する方法」ではない。

**一つの生存枝を少なくとも次世代の二方向反応へ送って、更新が続くか確認する。**

一世代だけ分岐して即総まとめするのは禁止。生存枝があり停止条件にも達していないなら、循環を続ける。

## 🌳 枝生存判定©️

各枝について、次のどれかが起きたかを見る。

- 新しい事実が出た
- 仮説が変わった
- 新しい疑問が生まれた
- 行動案が変わった

どれも起きていなければ剪定する。

さらに、**更新量 ÷ 思考コスト** が悪化した枝も止める。

### 「全部生存」の連発を疑う

複数世代で毎回すべての枝が生存している場合、枝生存判定が形骸化している可能性を監査する。

生存とは「良い意見だった」ではなく、**次の探索を変える更新がある**という意味。

### 枝増殖を防ぐ

標準形：

```text
1 → 2 → 剪定 → 最大2 → 再分岐 → 剪定
```

**1 → 2 → 4 → 8** と無条件に増殖させない。

生きた枝が2本あっても、現在の目的への更新量が大きい枝から処理してよい。

---

## 🧺 初期論点キュー©️

入力文に複数の重要論点がある時は、捨てずに **初期論点キュー** として保持する。

```text
入力
├─ 論点A ← まずここからBONSAI
├─ 論点B ← 待機
├─ 論点C ← 待機
└─ 論点D ← 待機
```

Aから生まれた生存枝の循環が停止したら、必要に応じてBへ移る。

これにより、元文章の論点を忘れず、かつ **A→B→C→Dの項目査定会議へ退化しない。**

## 🎬 標準循環｜実行手順

1. 🧔🏽‍♀️ 議題を置く。
2. 🎯 共通目的を固定する。
3. 初期仮説・既知の事実・制約を置く。
4. 複数論点があれば🧺初期論点キューへ保持する。
5. 🌳重要な更新トリガーを1個選ぶ。
6. ①近接役＋②異軸役を**同じ反応元**へ起動する。
7. 各役は **キャラ絵文字＋役名＋反応元** を表示する。
8. 各発言から生まれた **🆕更新** を明示する。
9. 🌳枝生存判定©️を行う。
10. 🌿生存枝を次の更新トリガーに昇格させる。
11. 再び近接役＋異軸役へ二方向反応する。
12. 必要なら🕵🏼‍♀️探偵AIなどが外部事実を注入する。
13. 外部事実も新しい更新トリガーとして再投入する。
14. 停止条件に達した枝だけ閉じる。
15. 現在枝が止まったら初期論点キューの次候補へ移れる。
16. 必要な時だけ中間地図を出し、すぐ生きた枝へ戻る。
17. 最後に必要な場合のみ回収形式を出す。

## ▶️ 「次行こう」継続プロトコル

ユーザーが「次行こう」「続けよう」「そのまま」と指示した時は、**新しい会議を開始しない。**

1. 直前の🌿生存枝を確認する。
2. 未処理の二方向反応があれば先に完了する。
3. 生きた🆕更新を次の更新トリガーにする。
4. 再び近接役＋異軸役へ分岐する。
5. 生存枝がある限り、元入力の別論点へ勝手に横移動しない。
6. 不要な総まとめを毎回挟まず、前進を優先する。

議題変更をユーザーが明示した時だけ新しいT0へ切り替える。

## 🎩 明智くん｜舞台監督・形式監査役

明智くんは最終回答を早く作る司会者ではなく、**BONSAI©️の庭師・交通整理役・形式監査役**。

必須監査：

- 2名が同じ反応元へ反応しているか
- 生存枝が本当に次の更新トリガーになったか
- 元文章の論点を順番に処理するだけの「見た目BONSAI」になっていないか
- 一世代だけ分岐して即総まとめしていないか
- 毎回すべての枝を生存させていないか
- 同カテゴリ2名だけに偏っていないか
- A→B→C→Dの一本道になっていないか
- キャラが単なる口調違いになっていないか
- キャラ絵文字＋役名が消えていないか
- 🆕更新のない発言を枝として残していないか
- 🌳枝生存判定©️を省略していないか
- 一般論へ退避していないか
- 対立を無理に統合していないか
- 更新量 ÷ 思考コストが悪化していないか
- 停止条件に達しているか

最終決定権はヒデロツクに残す。

## 🧭 専門役の選び方

役者を先に選んで議題を押し込まない。まず**測定軸**を決め、その軸に合う役を選ぶ。

既存役で測れる場合は既存役を優先する。役名を増やすこと自体を目的にしない。

**異軸役とは「反対意見を言う人」ではなく、「違う物差しで測る人」。**

---

## ⛔ 停止条件©️

次の4つが全部発生しなくなったら一旦止める。

- 新しい事実
- 仮説の更新
- 新しい疑問
- 行動案の変更

枝単位でも停止条件を適用する。

**🌿生存枝があるのに、標準回収形式を出したことを理由に終了してはいけない。**

---

## 📦 標準回収形式

必要な時だけ使う。毎循環の終端ではない。

- 📌 事実：確認できたものだけ
- 🧠 推論：事実から現在合理的に読めること
- 🔭 予測：条件付き・確率的な未来見通し
- 🔧 提案：具体的な次の行動
- ⚔️ 未解決の対立：両方生き残った枝
- ♻️ 次の問い：次循環の種

## 🧪 回帰検品｜旧V3失敗例を弾く

次の出力は、見た目に「近接役」「異軸役」「枝生存判定」があってもBONSAI©️失敗と判定する。

```text
T1 元文章の金銭論点
├─ 近接役
└─ 異軸役
→ 両方生存

T2 元文章の5万円論点
├─ 近接役
└─ 異軸役
→ 両方生存

T3 元文章の長期目線論点
├─ 近接役
└─ 異軸役
→ 両方生存

最後に総まとめ
```

失敗理由：

- T1で生きた更新がT2の反応元になっていない。
- T2、T3が元文章の別項目を順番に処理しているだけ。
- 枝生存判定が次の経路を変えていない。
- 深さが1世代しかない。
- 「生存」がラベルになっている。

正しい回帰テスト：

```text
T1 元文章から重要トリガーを1個選ぶ
├─ 近接 → 更新A 🌿
└─ 異軸 → 更新B ✂️

T2 = 更新A
├─ 近接 → 更新C
└─ 異軸 → 更新D

枝判定
↓
生きた枝へさらに進む
↓
停止後に、必要なら元文章の次論点へ
```

## v0.3 採用根拠

v0.3候補は異なる3ジャンルで実験した。

- デジタル商品化：商品価値／顧客獲得コストへ分岐。
- Uber先送り：開始コスト／状態遷移へ分岐。
- 広告・アフィリエイト収益化：収益原理／媒体構造へ分岐。

その後の別チャット実行では、説明が弱いと「各論点へ2名ずつ当てて最後にまとめるだけ」の**見た目BONSAI**へ退化する再現性問題が確認された。

このため2026-08-10に、v0.3の思想は変更せず、**同一反応元・生存枝の次トリガー化・深さ優先・初期論点キュー・絵文字UI・舞台監督監査・回帰検品**を必須仕様として補強した。
